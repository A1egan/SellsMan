# A1eG4n CRM 高密度工作台 UI 重构设计

日期：2026-08-25

## 1. 目标

把现有 CRM 从“功能都在，但信息层级分散”的看板，重构成适合 1366×768 / 1440×900 笔记本长期使用的高密度销售工作台。

本轮只改展示层与交互层，不改变任何业务数据：

- 不改用户数据结构
- 不改标签数据
- 不改备注
- 不改跟进历史
- 不改栏目字段
- 不改 localStorage key 与已有数据兼容逻辑
- 不改现有导入/导出数据语义

核心成功标准：打开页面后，销售第一眼能知道“今天优先跟谁”，一屏能看到更多学员，进入学员详情后能快速完成“记录沟通 → 安排下一步”。

## 2. 设计原则

### 2.1 工作优先于展示

CRM 不是数据展板，最重要的是让销售完成当天动作。因此视觉优先级按以下顺序排列：

1. 逾期跟进
2. 今日跟进
3. 高意向
4. 未安排下一步
5. 未来跟进
6. 纯统计信息

### 2.2 卡片只承担快速判断

看板卡片不再承载完整备注或复杂信息。卡片只保留：

- 用户编号
- 标签颜色点
- 跟进状态（逾期 / 今日 / 未来）
- 下一步动作一行
- 必要时的更新时间/意向提示

完整备注、标签管理和沟通历史全部进入详情面板。

### 2.3 一行三卡

所有栏目统一使用 3 张卡片一行，不再只有“待跟进”栏目特殊三列。

为了避免卡片过窄，栏目宽度由当前约 280px 提升到约 360–390px；横向滚动仍保留。目标是在 1366px 笔记本上同时看到约 3 个栏目及下一栏的一部分，让用户保有阶段感。

### 2.4 顶部层级压缩

当前“顶部工具栏 + 统计栏 + 任务栏”三层会占用大量首屏空间。重构后压成两层：

第一层：品牌 / 搜索 / 添加 / 菜单

第二层：任务概览

任务概览仅保留：

- 今日
- 逾期
- 未来
- 未安排
- 今日有效沟通 x / 20

栏目总数直接显示在各栏目标题中，不再单独占一整条统计栏。

## 3. 页面布局

### 3.1 顶部主栏

布局：

`A1eG4n 工作台 | 搜索 | 输入用户 | + 添加 | 菜单`

要求：

- 高度控制在约 52–56px
- 搜索框扩大，支持现有编号 / 备注 / 标签搜索
- “菜单”继续收纳：批量选择、批量添加、紧凑视图、导出 CSV、备份、导入、恢复
- 顶部保持 sticky

### 3.2 任务概览栏

紧贴主栏，使用紧凑 pill / segmented control：

`全部 | 今日 18 | 逾期 7 | 未来 35 | 未安排 1008 | 有效沟通 12/20`

行为：

- 点击任务 pill 继续沿用现有 taskFilter 逻辑
- 逾期使用红色强调
- 今日使用主色强调
- 有效沟通 KPI 靠右
- 顶部总占用控制在约 100px 内

### 3.3 看板

栏目仍按现有顺序：

- 待跟进
- 高意向
- 一般
- 低意向池
- 沉默用户

每栏：

- 宽度 360–390px
- 栏目标题固定显示 `栏目名 + 数量 + 筛选`
- 卡片区采用 `repeat(3, minmax(0, 1fr))`
- show more / empty state 跨三列
- 水平看板滚动保留
- 栏目自身不设置独立纵向滚动，继续让页面整体纵向滚动

## 4. 卡片设计

### 4.1 信息结构

示例：

`2877   ● ●`

`今日跟进`

`邀约直播`

卡片最多 3 个视觉层级：

- 第一行：编号 + 标签点
- 第二行：跟进状态
- 第三行：下一步动作，单行省略

### 4.2 状态表现

- 逾期：左侧 3px 红色强调条 / 红色状态文字
- 今日：左侧 3px 蓝色强调条 / 蓝色状态文字
- 未来：中性灰
- 未安排：不做强色块，避免整页过花
- 高意向栏目本身可用暖色标题标识，但不整张卡片染色

### 4.3 卡片交互

- 点击卡片：打开学员详情
- 拖拽：继续保留现有跨栏目移动
- 标签点：继续保留现有标签筛选
- 批量模式：继续保留 checkbox
- hover：轻微升起，不出现复杂按钮

## 5. 学员详情重构

现有详情内容保留，但从长表单重排为“高频动作优先”。

### 5.1 顶部摘要

固定显示：

- 学员编号
- 当前栏目
- 当前标签摘要
- 关闭按钮

### 5.2 跟进区（默认第一屏）

主要操作：

- 本次沟通结果
- 下次跟进时间
- 快捷时间：明天 / 3 天后 / 7 天后 / 清空
- 下一步动作
- 记录本次沟通按钮

该区应在 1366×768 下无需滚动即可完成主要销售动作。

### 5.3 历史区

- 最近沟通记录
- 默认展示最近 3–5 条
- 可滚动查看更多
- 保留“复制跟进摘要”

### 5.4 资料区

低频信息下沉：

- 备注
- 当前标签
- 所有标签
- 新建 / 编辑 / 删除标签
- 移入低意向池
- 删除用户

布局上与高频跟进区做明显分区，降低认知负担。

## 6. 视觉系统

### 6.1 总体风格

方向：克制、偏工具型、长期使用不疲劳。

- 页面主体使用白 / 浅灰 / 深灰
- 蓝色作为主操作色
- 红色只用于逾期和危险操作
- 绿色用于完成 / 成交 / 正向状态
- 橙色用于高意向提示

### 6.2 漫画背景

保留 `manga-bg.jpg` 作为个人风格，但显著弱化：

- 提高白色遮罩强度
- 降低对比度
- 不让背景纹理干扰卡片阅读

背景作为氛围存在，不作为主要视觉元素。

### 6.3 卡片与栏目

- 卡片圆角缩小到约 8px
- 阴影更轻
- 栏目背景用浅灰而非纯白大块
- 通过间距和细边框区分，而不是大量阴影

## 7. 笔记本适配

主要优化断点：

- 1366×768
- 1440×900

要求：

- 顶部区域不超过约 100px
- 第一屏能看到至少 5–6 行三卡布局
- 详情主要跟进动作在 768px 高度下容易完成
- 横向滚动条可见且不抢视觉

移动端只保证可用，不作为本轮第一优先级。

## 8. 保持不变的行为

以下现有功能必须继续工作：

- 单个添加用户
- 批量添加
- 搜索
- 标签筛选
- 栏目标签筛选
- 拖拽移动
- 批量移动 / 删除
- 紧凑视图（可重新定义视觉，但行为保留）
- CSV 导出
- 备份
- 导入
- 恢复
- 今日 / 逾期 / 未来 / 未安排筛选
- 沟通记录
- 下次跟进
- 有效沟通 KPI
- localStorage 数据兼容

## 9. 实施边界

本轮只重构 `index.html` 的 HTML / CSS / 前端交互展示逻辑。

如果现有函数需要为了 UI 重排做轻量调整可以修改，但不得改变存储字段含义或删除现有数据字段。

不引入框架，不新增后端，不做账号系统，不做云同步。

## 10. 验证要求

至少覆盖：

1. 所有栏目均为一行 3 卡
2. 1366px 宽度下栏目与卡片不溢出自身容器
3. 顶部菜单功能全部保留
4. 详情页主要操作可在 768px 高度下完成
5. 现有 localStorage 数据可正常读取
6. 拖拽、筛选、批量操作、跟进记录无回归
7. JavaScript 语法检查通过

## 11. 最终体验目标

用户打开 CRM 后，不需要先分析界面，而是立即得到三个答案：

1. 今天有多少人必须联系？
2. 哪些人最优先？
3. 点进去以后下一步该做什么？

整个设计服务于“每天稳定完成有效沟通”，而不是堆叠更多按钮或展示更多字段。
