# 客户看板五栏全览与拖拽性能设计

## 目标

在不改变 CRM 客户数据结构、栏目语义、标签/跟进字段和现有详情抽屉的前提下，解决两个桌面端高频问题：

1. 1440px 级桌面宽度下，客户看板默认能同时看到五个栏目，不再依赖横向滚动才能发现右侧栏目。
2. 拖动客户卡片时降低主线程和绘制压力，避免明显卡顿或短暂无响应。

## 已确认的视觉策略

- 1440px 及以上：五个栏目自动均分可用宽度并同时显示。
- 1440px 左右：每个栏目内客户卡片自动采用 2 列网格，保证编号、标签、跟进状态仍可读。
- 1800px/1920px 及以上：每个栏目内恢复 3 列网格，利用更宽空间提高密度。
- 小于约 1280px：退回横向滚动，不为了强行五栏而继续压缩文字。
- 不使用整体 `transform: scale()` 或浏览器 zoom；只压缩栏间距、padding 和局部布局。
- 左右移动按钮和底部横向滚动作为窄屏兜底继续保留，在五栏完全可见时可自动失去作用/禁用。

## 拖拽性能策略

- 新版 `workspace-v2.js` 接管旧看板的 `onDragStart/onDragOver/onDragEnd/onDrop`，避免修改体积很大的 legacy `index.html`。
- 拖动期间在 `body`/看板上挂轻量状态类，关闭卡片 hover 位移、阴影和非必要 transition，减少每帧绘制。
- `dragover` 仅在目标栏目发生变化时更新高亮；不在每次鼠标移动时重复清理所有栏目 DOM class。
- drop 后仍更新原 `users` 数据、`updatedAt` 并调用原持久化逻辑，保持数据语义兼容。
- drop 后优先只刷新来源栏、目标栏和统计/计数，不调用整页五栏 `render()`；若局部刷新依赖条件不满足，允许安全回退到 legacy render，但正常路径必须是局部刷新。
- 局部刷新必须尊重现有搜索、栏目过滤、`COLUMN_LIMIT`、展开状态和“显示更多”逻辑。

## 验收标准

- 1440×900、侧栏展开时五个 `.column` 都在看板可视宽度内，最右栏右边界不超过 `.board` 可视右边界（允许 2px 误差）。
- 1440 宽时栏目内部计算为 2 列客户卡片；1920 宽时为 3 列。
- 1200 宽时允许横向溢出，现有左右移动控制仍可用。
- 拖动开始后进入性能状态，hover transform/shadow 被禁用；拖动结束后恢复。
- 连续 `dragover` 同一目标栏不会重复遍历全部栏目清理 class。
- drop 后客户确实迁移到目标栏目并持久化；正常路径不触发完整五栏 legacy `render()`。
- 现有菜单层级、客户详情抽屉、批量操作、旧 CRM contract、Workspace contract 均保持通过。
