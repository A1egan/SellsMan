# A1eG4n 工作台 CRM v2 设计规格

日期：2026-08-26

## 1. 背景与目标

当前工作台以五列横向客户看板为核心，能够承载大量客户，但存在三个明显问题：

1. 主页面同时暴露过多数据，用户打开页面后第一眼看到的是“客户总量”，而不是“今天该做什么”。
2. 五列看板在电脑端仍然需要横向滚动，尤其在数据量大时视觉密度高、焦点弱、设计感不足。
3. 现有页面缺少明确的信息层级：首页、任务、客户管理、搜索、统计、批量运营全部混在同一张大页面里。

本次重构目标不是继续美化单一看板，而是将项目升级为一个“个人销售 CRM 工作台”：

- 首页以今日工作为核心，而不是客户池全貌。
- 客户看板保留，但降级为独立子页面。
- 使用固定左侧导航切换不同工作模块。
- 点击客户时使用右侧详情抽屉，不再用大弹窗阻断当前上下文。
- 新增可编辑、可勾选、可关联客户的今日/明日任务系统。
- 保持现有客户、标签、备注、历史记录、跟进时间、本地存储数据完全兼容。
- 视觉升级为“现代 CRM + 漫画/像素视觉语言”，提高辨识度，但不牺牲长期办公可读性。

## 2. 核心信息架构

应用采用单页应用式切换，不拆成多个物理 HTML 页面，避免 GitHub Pages 子路径路由问题。

使用 hash 路由：

- `#home`：今日作战台
- `#tasks`：今日任务
- `#board`：客户看板
- `#search`：客户搜索
- `#analytics`：数据统计
- `#batch`：批量运营

页面刷新后应保持在当前 hash 对应的子页面。

### 2.1 左侧导航

左侧导航默认展开，可折叠。

展开宽度约 220–240px；折叠后约 64px，仅保留图标。

主导航：

1. 今日作战台
2. 今日任务
3. 客户看板
4. 客户搜索
5. 数据统计
6. 批量运营

底部低频入口：

- 设置
- 备份
- 导入/导出

当前页面应有明显高亮状态。折叠后鼠标悬停图标显示名称。

## 3. 首页：今日作战台

首页不是数据大屏，而是“今天要干什么”的工作入口。

### 3.1 页面信息优先级

一级：今日计划

二级：CRM 雷达

三级：明日计划、最近处理客户、其他辅助信息

首页必须主动留白，不追求把每一寸空间填满。

### 3.2 今日计划

今日计划占首页最大面积，支持：

- 新增任务
- 编辑任务
- 删除任务
- 勾选完成
- 拖拽排序
- 优先级：普通 / 重要 / 紧急
- 关联 CRM 客户

任务可分为两类：

1. 普通任务，例如“整理直播名单”“群内发通知”。
2. 关联客户任务，例如“回访 #2877”。

点击关联客户编号时，直接打开右侧客户详情抽屉。

已完成任务自动沉到列表底部，并弱化显示；可折叠查看。

### 3.3 CRM 雷达

CRM 雷达不是装饰性统计，而是快捷行动入口。

至少包含：

- 逾期跟进
- 今日待跟进
- 高意向待处理
- 今日有效沟通进度，例如 13 / 20

点击任一数字直接进入对应任务/客户名单。

CRM 自动生成的“今日跟进”“逾期”不直接写入个人任务列表，避免自动任务污染手写计划。

### 3.4 明日计划与转入逻辑

明日计划与今日计划共享相同基础能力：新增、编辑、删除、排序、关联客户。

明日计划不会因为日期跨过零点而自动进入今日计划。

创建“明日计划”时，任务记录目标日期，但初始状态为 `planned`。第二天首次进入首页时，如果存在目标日期已到且仍为 `planned` 的任务，显示轻提示：

- 全部转入今日
- 选择转入
- 暂不处理

处理规则：

- “全部转入今日”：将这些任务状态改为 `active`，进入今日计划。
- “选择转入”：只有选中的任务改为 `active`；未选中的继续保留为 `planned`。
- “暂不处理”：将这些任务标记为 `deferred`，当天不进入今日计划，也不在本次页面打开时重复弹出提示；任务仍保留在历史中，可手动恢复或重新安排。
- 已完成任务不再参与转入提示。

这样可以实现用户已确认的原则：第二天先提示，由用户决定是否把明日计划接入今日，而不是系统自动污染今日列表。

### 3.5 最近处理客户

首页显示最近操作过的少量客户，例如最近 3–5 位。

点击后直接打开右侧详情抽屉。

该模块必须保持轻量，不能变成另一份客户列表。

## 4. 今日任务页

今日任务页用于集中处理 CRM 系统层面的跟进任务，而不是手写 Todo。

推荐分组：

- 逾期
- 今日
- 即将到期
- 未安排

支持按优先级、客户阶段、标签筛选。

从任务列表点击客户后右侧打开详情抽屉，并保持当前列表位置。

## 5. 客户看板页

保留现有五个客户阶段：

- 待跟进
- 高意向
- 一般
- 低意向池
- 沉默用户

该页面主要用于：

- 全局浏览
- 拖拽分层
- 批量运营
- 阶段管理

看板不再承担首页职责。

现有客户数据、栏目 ID、拖拽逻辑、标签逻辑、导入导出语义必须保持兼容。

卡片仍可采用三卡一行，但密度、内容层级应重新评估。卡片默认只展示最关键字段，详细信息交给右侧详情抽屉。

## 6. 客户搜索页

客户搜索页以快速定位为目标，而不是全量浏览。

支持：

- 客户编号搜索
- 标签搜索
- 备注关键词搜索（若现有数据可支持）

搜索结果尽量简洁。点击结果打开右侧客户详情抽屉。

## 7. 数据统计页

第一版只做对当前销售执行最有价值的指标，不做复杂 BI。

优先指标：

- 今日有效沟通
- 每日有效沟通趋势
- 各客户阶段数量
- 高意向变化
- 跟进任务完成情况
- 活动标签/来源的客户数量（在现有标签数据可支持的范围内）

统计页保持现代图表风格，不做游戏化仪表盘。

## 8. 批量运营页

将低频但重要的批量能力从主工作区中剥离，集中管理：

- 批量选人
- 批量加/删标签
- 批量移动阶段
- 批量添加客户
- 导入
- 导出 CSV
- 数据备份
- 数据恢复

现有导入导出和备份语义必须保持兼容。

## 9. 右侧客户详情抽屉

点击客户后，不再弹出阻断整个页面的大弹窗，而是从右侧滑出详情抽屉。

默认关闭；只有点击客户时才打开。

建议宽度 360–420px，根据屏幕宽度自适应。

抽屉结构：

1. 顶部：客户编号、当前阶段、标签
2. 本次跟进：结果、时间、下一步动作
3. 快捷安排：下次跟进时间、关联任务
4. 最近历史：默认展示最近 5 条，可展开
5. 基础资料：备注、标签管理、阶段移动等低频操作

关闭抽屉后必须保持原页面滚动位置和筛选状态。

## 10. 新任务数据模型

新增任务数据必须和现有客户数据分离，单独使用新 localStorage key：

`sales_work_tasks_v1`

建议字段：

- `id`
- `title`
- `plannedDate`
- `status`：`planned` / `active` / `deferred` / `completed`
- `priority`：`normal` / `important` / `urgent`
- `linkedCustomerId`（可为空）
- `createdAt`
- `activatedAt`（可为空）
- `completedAt`（可为空）
- `deferredAt`（可为空）
- `sortOrder`

状态含义：

- `planned`：未来计划，日期到达后等待用户决定是否转入今日。
- `active`：已进入当前工作列表。
- `deferred`：用户选择暂不处理，保留但不自动进入今日。
- `completed`：已完成。

第一版明确不加入：

- 周期任务
- 子任务
- 复杂提醒系统
- 多人协作
- 云同步

任务历史按日期和状态保留，用于以后查询“某天计划了什么、完成了什么、哪些被暂缓”。

## 11. 数据兼容原则

这是本次重构的硬约束。

不得破坏：

- 现有客户数据
- 现有客户编号
- 栏目/阶段映射
- 标签
- 备注
- 跟进历史
- 下次跟进时间
- 有效沟通统计
- 导入/导出字段语义
- 现有 localStorage 客户数据 key 及其可读取能力

任务系统只能作为新增能力存在。

若需要迁移 UI 层结构，必须做到旧数据打开新版后无需人工处理即可正常显示。

## 12. 视觉系统：Modern Comic Ops

视觉定位：现代 CRM 骨架 + 漫画分镜 + 像素图标 + 少量游戏化反馈。

目标是“像一个有自己世界观的销售工作台”，而不是普通 SaaS 模板，也不是纯复古小游戏。

### 12.1 背景

- 不再整页大面积铺漫画背景图。
- 主工作区以深灰/米白/暖灰纯色为主。
- 可加入非常轻的漫画网点、扫描线或纸张纹理。
- 现有漫画图可以作为局部品牌装饰、空状态或左侧品牌区域元素。

### 12.2 配色

基础：黑、深灰、米白、浅灰。

状态色：

- 红：逾期、危险、关键提醒
- 黄橙：今日、进行中
- 绿：完成
- 蓝紫：常规交互、普通状态

不得依靠大量高饱和颜色制造“设计感”。

### 12.3 卡片与边框

- 卡片以白色/暖灰为主。
- 边框略比传统后台更有存在感，形成轻度漫画分镜感。
- 圆角适中，不使用过度圆润的 SaaS 模板风格。
- 阴影克制，优先靠层级、边框和留白建立视觉秩序。

### 12.4 图标与字体

- 导航和状态图标统一使用像素化或线性像素图标语言。
- 正文继续使用高可读系统字体。
- 像素字体只允许出现在极少量数字/HUD/装饰处，不得用于大段正文。

### 12.5 动效

只保留短促、功能性的微动效：

- 任务勾选后 100–200ms 的缩放/像素闪动
- 侧边栏折叠
- 客户详情抽屉滑入/滑出
- 页面切换轻微过渡

不做庆祝动画、不做持续闪烁、不做影响办公注意力的效果。

## 13. 电脑端适配

主要使用场景为电脑端，而不是只针对单一笔记本分辨率。

优先保证：

- 常见 1366×768 笔记本可正常使用
- 1440×900 / 1536×864 有良好空间利用
- 1920×1080 及更宽显示器不会过度拉伸信息密度

主内容区应设置合理最大宽度或动态栅格，不允许在大屏上把每个模块无限横向拉宽。

移动端不作为本次第一优先级，只需要保证页面不完全不可用。

## 14. 第一版成功标准

重构完成后，应满足：

1. 打开应用默认进入“今日作战台”，而不是五列客户墙。
2. 用户在首页 5 秒内能知道今天最重要的任务和 CRM 风险。
3. 左侧导航可展开/折叠，并可无刷新切换子页面。
4. 今日/明日任务可新增、编辑、删除、勾选、排序、关联客户。
5. 第二天能处理前一天的明日计划：全部转入、选择转入或暂不处理。
6. 点击任何客户都能使用统一右侧详情抽屉。
7. 客户看板仍保留五阶段和原有管理能力。
8. 旧客户数据无需迁移操作即可继续使用。
9. 页面明显减少“数据墙”感，视觉焦点优先落在当前工作而不是总客户量。
10. 漫画/像素语言可被识别，但连续办公时不影响阅读和操作效率。

## 15. 明确不做的内容

本轮不加入：

- 多账号登录
- 多销售协作
- 服务端数据库
- 云同步
- 微信自动发消息
- 自动读取微信聊天
- AI 自动销售回复
- 周期任务
- 复杂通知系统

这些可以在未来业务需要时单独设计，不与本轮 UI/工作流重构混在一起。
